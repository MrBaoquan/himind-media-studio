# 剪辑方向的价值定位与非目标

> 日期：2026-10-19
> 一句话：**我们做的是“AI 视频生产系统里的精修面”，不是另一款达芬奇/CapCut。**

## 一、价值主张

| 价值 | 说明 |
| --- | --- |
| AI 到成片的确定性 | Plan → Storyboard → Timeline → Render 每一层可校验、可复现 |
| 可解释的修改 | AI 产出命令而非直接改像素；每条修改可 diff、可撤销、可回放 |
| 可沉淀的知识 | 模板、风格、约束、QA、坑记录持续复用，而不是每次从零提示 |
| 项目与资产治理 | 创意包、项目、参考包、产物、许可证有血缘关系 |
| 批量与系列化 | 一次生成多条，逐条可调、可重试、可交付 |
| 本地优先与扩展生态 | 能力以插件/资产包/Skill/Workflow 沉淀，不被单一模型绑定 |

## 二、非目标（明确不做）

- 不做完整 NLE：Fusion 节点、Fairlight 调音台、完整调色台、跟踪、3D；
- 不做自由时间轴优先的创作方式：AI 对话与创作包仍是主入口；
- 不做特效插件 SDK、第三方转场市场（至少当前阶段）；
- 不追求“所有 Resolve 功能都有”；
- 不把剪辑 UI 做成产品中心。

## 三、从达芬奇借什么、不借什么

借：

- 媒体池、源/节目监视器、Inspector、多轨时间轴的空间组织；
- Blade / Lift / Ripple Delete / Insert / Overwrite 的基本语义；
- 入出点、三点编辑、吸附、J/K/L 走带；
- “时间轴是制作结果”的心智。

不借：

- 全量页面（Media/Edit/Fusion/Color/Fairlight/Deliver）；
- 复杂修剪（Roll/Slip/Slide）作为首版必做；
- 调色、跟踪、多机位、关键帧曲线作为核心卖点。

## 四、剪辑层在系统中的位置

```text
AI 创作（主入口）
  → 创作包 / 分镜（意图）
  → Timeline（制作结果，可精修）
  → Renderer
  → QA / 交付
```

时间轴是“当 AI 结果需要人工校正时的精修面”，不是每天的新起点。

## 五、范围分层

### Core（必须有）

- Timeline v1（帧时间）；
- Insert / Overwrite / Blade / Lift / Ripple Delete；
- 单视频轨 + 音频轨 + 字幕轨；
- 命令总线、撤销/重做、diff；
- 媒体池/代理/元数据；
- AI 命令生成与预览。

### Precision（有了更好）

- Ripple Trim；
- Link A/V、轨道目标；
- 基础转场、画中画；
- 字幕烧录；
- 交付预设。

### Deferred（明确后置）

- Roll / Slip / Slide；
- 调色/LUT；
- 关键帧/速度曲线；
- 多机位、跟踪、Fusion 式合成。

## 六、成功指标

- 从主题到“可批准成片”的时间；
- AI 生成剪辑命令的采纳率；
- 人工返工次数与返工时长；
- 模板/风格/约束的复用率；
- 同一 Timeline 重复渲染的确定性通过率；
- 批量项目中单条失败率与恢复率。

## 七、功能决策规则

任何新剪辑功能先问三件事：

1. 是否缩短“主题 → 可批准成片”的路径？
2. 是否让 AI 结果更可解释、可回退、可复用？
3. 是否是短视频交付的真实刚需？

三个都为“否”，就不做；只有一个为“是”，进入 Precision；全部为“是”，才进入 Core。

## 八、结论

方向正确，但价值不在“功能数量对齐达芬奇”，而在：

> **用 AI 把创作意图变成可验证的制作结果，并允许人在关键处精确修正。**

剪辑层应保持“窄、准、可回退”，避免把产品拖回传统 NLE 的复杂度。
