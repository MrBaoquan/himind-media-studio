# 合肥轨道交通数据源评估

> 调研日期：2026-10-18  
> 目标：为 `transit-network` 提供真实线路、站点、换乘和开通年份数据  
> 结论：**目前没有找到合肥轨道官方公开发布的 GTFS / GeoJSON / 开放 API；最可行的是“官方信息校准 + OSM 几何 + Wikidata/Wikipedia 交叉校验”的混合方案。**

## 一、结论先行

| 需求 | 推荐来源 | 说明 |
| --- | --- | --- |
| 线路编号、站名、开通日期、运营状态 | 合肥轨道官网/公众号/官方 App、合肥市与安徽省发改委公告 | 权威，但主要是新闻/公告，不是机器可读数据 |
| 线路几何、站点坐标、换乘关系 | OpenStreetMap（Overpass API） | 已验证可用；ODbL 许可；适合作为几何底稿 |
| 线路实体、开通年份、跨语言名称 | Wikidata | CC0；适合做 ID 和年份校验 |
| 当前运营线路/车站总数 | Wikipedia（中文） | CC BY-SA；适合交叉校验，不作为唯一来源 |
| POI 坐标补全/人工核对 | 高德/百度/腾讯地图 API | 受商业条款限制，不适合批量存储和再分发 |
| 规划线路/S1/四期规划 | 合肥市自然资源和规划局、安徽省发改委公开文件 | 权威规划信息，但通常是 PDF/图片，不含精确坐标 |

## 二、官方渠道

### 1. 合肥轨道官网

```text
https://www.hfgdjt.com/
```

实际情况：

- 官网可访问，但首页是带反爬/加密会话的 JS SPA；
- 没有发现公开的 GTFS、GeoJSON、线路 API；
- 适合获取新闻、开通公告、线路图、车站服务信息；
- 线路图图片有版权，不能直接复制进 Style Pack，只能参考视觉语言并自绘。

### 2. 合肥市 / 安徽省公共数据开放平台

```text
https://data.hefei.gov.cn/
https://data.ah.gov.cn/
```

实际情况：

- 从当前网络环境无法完成 TLS/连接验证；
- 这类平台通常需要实名注册，且不保证有“轨道交通线路几何”数据集；
- 如果本地能访问，优先搜索：
  - `轨道交通`
  - `地铁`
  - `公交`
  - `线网`
  - `站点`
- 即使有站点表，通常也只有名称/地址，不一定有线路折线和换乘关系。

### 3. 规划与批复文件

可关注：

- 合肥市自然资源和规划局：线网规划、控制性详细规划；
- 安徽省发展和改革委员会：轨道交通工程可行性研究报告批复；
- 合肥市轨道交通集团有限公司：线路开通公告。

这些文件适合确认：

- 线路编号与走向；
- 一期/二期/延长线范围；
- 开通年份；
- 车站正式名称；
- S1、7 号线剩余段等在建状态。

局限：

- 多为 PDF/图片，不能直接作为渲染数据；
- 规划图不是运营图，可能包含未开通线路；
- 需要人工把站名和线路关系录入结构化数据。

## 三、OpenStreetMap（推荐几何底稿）

### 已验证查询

```overpassql
[out:json][timeout:120];
area["name"="合肥市"]->.a;
rel(area.a)["route"="subway"]["network"="合肥轨道交通"];
out body;
>;
out body;
```

验证时间：

```text
2026-10-18T14:31:51Z
```

验证结果：

```text
route relations: 16（1/2/3/4/5/6/8 号线，双向/支线拆分）
named stop nodes: 420
distinct station names: 198
```

> 注意：198 是 OSM 节点名称去重结果，不能直接等同于“195 座运营车站”。OSM 可能包含在建/延伸段站点，且上面的 `route=subway` 查询没有完整包含 7 号线。必须用官方运营状态过滤后再计数。\n\n扩展查询（包含 7 号线与 S1）：

```text
23 个 relation
其中 7 号线、S1 的 route 标签为空，说明 OSM 里可能仍是在建/未完整映射状态
```

### 优点

- 有线路折线、站点节点、换乘站、线路颜色、运营方等字段；
- 有 `opening_hours`、`from`/`to`、`ref` 等运营信息；
- 可直接通过 Overpass 获取，适合脚本化；
- 数据更新较快，覆盖 1–8 号线和 S1 关系。

### 注意

- OSM 是社区数据，不是官方数据；
- 双向线路会拆成两个 relation，需要按 `ref` 合并；
- 同一车站可能有两个方向/两个站台节点，需要按站名或 `stop_area` 去重；
- 7 号线、S1 可能不完整，必须用官方公告校验；
- 许可为 **ODbL 1.0**：需要署名，衍生数据库分发时需要同许可共享。

## 五、商业地图 API

可选：

- 高德开放平台；
- 百度地图开放平台；
- 腾讯位置服务。

适合：

- 用 POI 搜索补全站点坐标；
- 人工核对站名与出入口；
- 生成对照表。

不适合：

- 批量抓取后长期存储；
- 直接把 POI 数据打包进开源资产包；
- 绕过商业条款做再分发。

## 六、推荐的数据管线

```text
官方公告 / Wikipedia / Wikidata
        ↓ 站名、线路编号、开通年份、运营状态
OSM Overpass
        ↓ 线路折线、站点坐标、换乘关系
规范化脚本 dev/import-hefei-metro.mjs
        ↓ 去重、合并双向、投影、简化
data/hefei-metro/hefei-metro.json
        ↓
input/data.json + input/labels.json
        ↓
transit-network 渲染 + label.validate + 视觉 QA
```

### 规范化规则

1. 按 `ref` 合并双向 relation；
2. 站点优先按 `stop_area` 去重，其次按站名 + 距离聚类；
3. 换乘站 = 被两条及以上线路引用的站点；
4. 线路颜色优先使用官方线路图色值，OSM `colour` 作为回退；
5. 开通年份以官方公告为准，Wikipedia/Wikidata 做交叉校验；
6. 在建线路单独标记 `status: under_construction`，画面用虚线/低饱和色；
7. 所有输出写入 `provenance`：

```json
{
  "source": "OpenStreetMap",
  "license": "ODbL-1.0",
  "osm_timestamp": "2026-10-18T14:31:51Z",
  "official_crosscheck": ["hfgdjt.com", "wikipedia"],
  "generated_at": "..."
}
```

### 质量门禁

- 每条运营线路至少有一个起终点；
- 站点坐标在合肥合理范围内；
- 站点不在线路折线之外（容差内）；
- 换乘站至少被两条线路引用；
- 站名与官方清单一致，差异进入 `name_mismatches.json`；
- 所有站名通过 `media.workbench.label.place` / `label.validate`；
- 画面标注数据来源与“非官方示意图/不用于出行”边界。

## 七、许可与交付边界

| 来源 | 许可 | 交付要求 |
| --- | --- | --- |
| OSM | ODbL 1.0 | 署名 OpenStreetMap contributors；衍生数据库同许可 |
| Wikidata | CC0 | 无强制署名，建议保留来源 |
| Wikipedia | CC BY-SA | 署名 + 相同方式共享 |
| 官方公告/线路图 | 版权归原作者 | 只提取事实信息，不复制图片 |
| 高德/百度/腾讯 | 商业条款 | 不作为开源数据再分发 |
